## 2026-07-18 - Bitmasking for Perfect Reversion/Trancation Behavior in Lookup-Based Binary Conversion
**Learning:** In the character-to-binary converter, characters with code values above 255 (e.g. non-ASCII or high unicode characters) are translated in the original loop using `charCode & (1 << j)` for `j = 7` down to `0`. Because the bitwise operations check only the first 8 bits, this is mathematically identical to applying `charCode & 0xFF` and then fetching from a pre-computed 256-element lookup table. This prevents logic mismatch regressions for non-ASCII characters while retaining maximum performance.
**Action:** When designing lookup tables for bitwise-truncated character inputs, always bitmask with the size of the lookup table (e.g. `0xFF`) to guarantee both exact logical equivalence and safe bounds checking in the O(1) table lookup.
